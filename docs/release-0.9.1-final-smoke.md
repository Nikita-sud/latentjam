# 0.9.1: заключительная проверка Android APK

Дата: 15 октября 2026. Код и APK: `b7d5a8bb7242ebf15cbf803a3396d18d26843389`,
ветка `codex/adversarial-0.9.1`, чистое дерево при сборке.

**Рекомендация: этот Android-кандидат можно выпускать на GitHub.** В проверенных
сценариях блокеров не осталось. Это не означает, что подтверждено решение всех
случаев авторов обращений: ограничения ниже остаются.

## Что обнаружила заключительная проверка

В предыдущем APK `d7ae2800` перенос текущего файла с новым MediaStore ID сохранял
плейлист и избранное, но Refresh сбрасывал позицию примерно с 51 секунды на начало.
Media3 заменяет источник при смене URI; одного сохранения mediaId недостаточно.
Обычный Refresh без переноса продолжал воспроизведение корректно.

Исправление сохраняет позицию только при замене источника текущего элемента.
Индекс, порядок очереди, repeat/shuffle и playing/paused сохраняются. Достоверный
URI самого MediaItem имеет приоритет; скрытый контроллером URI берётся из прежнего
дескриптора. Main.immediate не отдаёт управление обновлению каталога между
публикацией библиотеки и сохранением прежних дескрипторов.

## Проверки

- Опубликованный APK 0.9.0 подтверждён по digest GitHub release asset:
  `3201216384ac4708a97824cf1bc7cae35d172f3455a85ebf29091bb5a1bf42ca`.
- Обновление 0.9.0 → первый кандидат `d7ae2800` на LJ-api30/Android 11 сохранило
  побайтово избранное, плейлист, историю и настройки; очередь восстановилась в UI.
  Затем поверх него установлен итоговый `b7d5a8bb`. SHA-256 установленного base.apk
  совпал с финальным ARM64-артефактом. Изменение между кандидатами затрагивает
  восстановление позиции, а не формат пользовательских данных.
- После исправления заново прошли **222 playback host-теста**, **13 playback
  device-тестов** и **10 library device-тестов**, без ошибок и пропусков.
  Из них пять новых сценариев проверяют playing, paused, другой элемент + tag-only,
  приоритет реального источника и два одинаковых mediaId с активным вторым.
- Отрицательный контроль без восстановления позиции дал два сбоя из трёх;
  другой элемент/tag-only прошёл. С исправлением весь набор зелёный.
- Итоговый production APK проверен через обычный UI. Синтетический MP3 с заранее
  прочитанным уникальным release-track ID перемещён и переименован во время
  воспроизведения. После Refresh логический ID остался `44`, MediaStore ID стал
  `54`; новые путь и название подхватились. Позиция **35 809 → 40 484 мс** при
  прошедших **4 740 мс**, состояние PLAYING, ошибок нет. Сброса на начало нет.
- После перезапуска перенесённый файл воспроизводится из прежнего плейлиста.
  Избранное и плейлист остались побайтово прежними; исходные записи истории
  сохранены. Буфер crash-log пуст. Это проверка эмулятора, не прослушивание на
  физическом телефоне и не гарантия отсутствия краткого прерывания звука при замене.
- Три APK собраны из чистого исходника; DEX, native libraries, ELF/ZIP 16 KiB и
  точные хеши уменьшенного ORT прошли проверку. Сборка Gradle: 58 секунд.

Более ранние 2 806 host и 1 691 iOS тестов описаны в
[проверке issue #17](issue-17-track-identity-validation.md). Здесь заново запускались
затронутые playback-тесты и Android integration; прежние результаты не выдаются
за новый полный прогон. iOS-код последним исправлением не менялся.

закрытие issues, push, merge, тег и публикация в ходе проверки не выполнялись.
