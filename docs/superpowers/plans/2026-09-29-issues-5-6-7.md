**Interfaces produced:**
- `public object TextRepair { public fun repair(text: String): String; internal fun decodeUtf8Strict(bytes: ByteArray, from: Int = 0, to: Int = bytes.size): String? }`

**Decisions (binding):**
- `repair(text)`:
  - If no char is ≥ U+0080, return `text` unchanged. This is the fast path.
  - Otherwise map every char back to one byte. U+0000–U+00FF map to the same byte value; this covers Latin-1 and the C1 controls that Android emits for cp1252's undefined bytes 0x81, 0x8D, 0x8F, 0x90, 0x9D. The 27 cp1252-specific characters (€ ‚ ƒ „ … † ‡ ˆ ‰ Š ‹ Œ Ž ‘ ’ “ ” • – — ˜ ™ š › œ ž Ÿ) map to their cp1252 byte. Any other char means the text is not this kind of mojibake: return it unchanged.
  - Decode the bytes as strict UTF-8. Reject overlong forms, surrogates (ED A0–ED BF), code points above U+10FFFF, truncated sequences and stray continuation bytes. If decoding fails, return the text unchanged. If it succeeds, the result holds at least one multi-byte sequence, because a byte ≥ 0x80 was present; return it.
  - Apply at most twice, for double-encoded text. Stop as soon as a pass changes nothing.
- Id3Text encoding 0 (ISO-8859-1): when the frame's bytes contain a byte ≥ 0x80 and decode as strict UTF-8, use the UTF-8 decoding; otherwise keep the Latin-1 decoding. This is the same rule applied at byte level, and it fixes `TagFacts` (genres, artists, language), USLT lyrics and the tag editor's reads at one point. Check that the plan-1 tag tests still pass: a restated repaired value is equal on read-back, so the frame is kept byte for byte.
- Android: apply `TextRepair.repair` to title, artist, album and genre in `queryTracks` (e.g. inside a helper next to `knownOrNull`). iOS: apply it to every tag-derived display string (title, artist, album, genre, and any album-artist or artists string).
- Do NOT repair file names, folder paths or URIs.
- Also check `LibraryCatalog.normalizedKey`: once the inputs are repaired it needs no change. Add a test showing that two tracks, one "Grüße" and one "GrÃ¼ÃŸe", given as MediaStore would deliver them and passed through the same repair helper the Android path uses, land in one album group. If the Android helper is private, test `TextRepair` plus the grouping on repaired strings.

### Task 4: Lyrics from a `.lrc` file next to the song (#6, part 2)

**Files:**
- Create: `core/library/src/commonMain/kotlin/io/github/nikitasud/latentjam/library/tags/SidecarLyrics.kt` (decoding + choice)
- Test: `core/library/src/commonTest/kotlin/io/github/nikitasud/latentjam/library/tags/SidecarLyricsTest.kt`
- Modify: the Android and iOS lyrics readers (`TrackLyrics.android.kt`, `TrackLyrics.ios.kt`) and the lyrics search index path if it reads lyrics
- Create/modify (Android): a small store of granted lyrics folders plus a Settings entry to add and remove folders (find the settings screen; follow its row style)
- Modify: all 18 strings.xml files for the new Settings strings
- Test: composeApp tests for the pure mapping from a track's absolute path to a SAF document id

**Decisions (binding):**
- `SidecarLyrics.decode(bytes: ByteArray): Lyrics?`:
  - A UTF-8 BOM means UTF-8.
  - A UTF-16 LE or BE BOM means UTF-16.
  - Otherwise use strict UTF-8 (`TextRepair.decodeUtf8Strict`).
  - If that fails, return null. The file is in an unknown legacy code page, and guessing shows garbage.
  - Normalize CRLF and CR to LF, then `EmbeddedLyrics.parse`.
  - Files larger than 1 MiB are declined without reading them fully.
- `SidecarLyrics.choose(embedded: Lyrics?, sidecar: Lyrics?): Lyrics?`: synced beats plain. On a tie the sidecar wins, because the user put that file there on purpose. Null only when both are null.
- Sidecar file name: the audio file's name with its extension replaced by `.lrc`, matched case-insensitively (`.lrc` or `.LRC`), in the same folder. Example: `Song.mp3` → `Song.lrc`.
- iOS: imported files live in the app's Documents. Look for the sibling next to the resolved file path with NSFileManager. No permission is needed.
- Android API ≤ 28: READ_EXTERNAL_STORAGE is granted for playback, so read the sibling directly through `java.io.File`, using the absolute path from MediaStore's `DATA` column. The query pattern is in `filePathOf` in `TrackTagWriter.android.kt`.
- Android API ≥ 29: scoped storage blocks non-media files, so use the Storage Access Framework.
  - Settings gets an entry, in the lyrics or library section (whichever exists, else near library sources), named "Folders with .lrc files". Its actions are Add folder (`ACTION_OPEN_DOCUMENT_TREE` with `takePersistableUriPermission` for READ) and Remove, which releases the permission.
  - Granted tree URIs are persisted app-private.
  - Lookup: take the track's absolute path from `DATA` and map it to an ExternalStorageProvider document id. `/storage/emulated/<user>/rest` becomes `primary:rest`, and `/storage/<VOLUME-ID>/rest` becomes `<VOLUME-ID>:rest` (volume ids upper-case as the provider uses them).
  - For each granted tree whose root document id is a prefix of that id, followed by `/` or equal, build the child URI with `DocumentsContract.buildDocumentUriUsingTree(tree, candidateDocId)` for `Name.lrc`, then `Name.LRC`, and open it. FileNotFoundException means not there. A SecurityException means the grant was revoked: drop it quietly from the store.
  - Keep that path-to-document-id mapping a pure function in commonMain or androidMain with host tests.
  - Only trees from `com.android.externalstorage.documents` are matched; ignore other providers.
- Both platforms: read the embedded lyrics and the sidecar, then `SidecarLyrics.choose`. A sidecar failure of any kind must fall back to the embedded lyrics, never throw.
- The lyrics search index, if it caches by revision: a change in the set of granted folders must invalidate what it cached as "no lyrics". Put the grant set in the revision or clear the cache on change. Adding a new `.lrc` to an already granted folder is picked up the next time the index is rebuilt; state the exact behavior in the report.
- New strings go into all 18 files with real translations. They cover the settings title, a one-line explanation (Android asks which folder to allow; files named like the song with .lrc are used), the add action and the remove action. On iOS the entry is not shown.

**Tests:**
- decode: BOM variants, CRLF, invalid UTF-8 → null, the size cap.
- choose: all combinations.
- The document-id mapping: primary, SD card, a secondary user (`/storage/emulated/10/...`), a path outside any tree, a tree that is a prefix of the name but not of a folder (`primary:Music` must not match `primary:MusicVideos/...`).
